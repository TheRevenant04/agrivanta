# Agent permissions and security boundaries

This note applies to every agent, subagent, skill, and headless run in
this repository. Rules marked *enforced* are machine-checked by
`opencode.json` and the guardrails plugin
(`.opencode/plugins/guardrails.js`); the rest are policy that agents
must follow.

## Enforced automatically

Denied bash commands — no exceptions for agents; a human may run them
deliberately:

- `git push --force*` / `git push -f*` — never rewrite remote history
- `git reset --hard*`, `git clean*` — never discard work
- `git commit --amend*`, `git rebase*` — never rewrite published history
- `rm -rf*` — never bulk-delete

The guardrails plugin logs every bash command and file edit to
`.opencode/guardrails.log` (gitignored) so each session leaves an audit
trail, and throws on the denied commands above as defense in depth.

`.env` and `.env.*` files are unreadable by agents (opencode denies
reading them by default; `.env.example` stays readable).

## Policy

- Stage only files related to the current task. Never commit unrelated
  changes, secrets, keys, or tokens.
- Never echo, log, or commit credentials. The `gh` token comes from the
  environment; do not print it.
- The MCP server (`mcp-server/`) is read-only: it reads `_docs/tasks.md`
  and lists GitHub issues. It must never gain write tools.
- QA never edits code; the engineer never closes issues; only the
  orchestrator closes an issue after a QA PASS (see `_docs/process.md`).
- Do not bypass hooks or checks (`--no-verify`) or weaken permission
  rules to make a task pass.

## Raising access

If a task genuinely needs a denied command, stop and ask the human to
run it. Do not edit this file, `opencode.json`, or the guardrails plugin
to grant yourself access.
